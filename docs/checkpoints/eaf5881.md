# Workflow checkpoint — projected surface sculpt strokes

Base remote revision: `847619fb618834a5b63f424c58b4cecd566a672d`.
Implementation revision: `eaf5881b9919ab7bee38cff1a29d8a73bf007992`.
Capability: project authored geometry-local stroke paths to an intended indexed support surface, then derive topology-aware edge-distance sculpt masks that do not bleed through free space onto nearby disconnected layers.

## Accepted change

`src/lib/surface-stroke.js` adds `projectSurfacePath()` and `surfacePathSelection()` as a support-aware companion to the existing free-space `pathSelection()` API. Projection resamples an authored polyline, resolves each sample through the existing triangle spatial index, and stores JSON-safe triangle/corner/barycentric ownership. Selection reconstructs those samples on the current same-topology form, seeds the owning triangle corners, and runs a radius-bounded Dijkstra search over current mesh-edge lengths. Optional named face regions constrain support binding and propagation independently from the sculpt operation itself.

The operation is deliberately an edge-geodesic approximation rather than a continuous surface-geodesic solver. Mesh density and triangulation affect the field. Same-topology position edits are supported through recorded barycentric ownership; changed triangle/corner topology fails explicitly and requires re-projection or a future operation-specific remap contract.

This checkpoint also fixes the existing `setAttrribute` typo in the geometry-sculpt rig-ownership test. That typo was the only failure in the prior main Pages test job and prevented the test from reaching the intended pre-rig rejection assertion.

## Research used

See `docs/research/surface-stroke-projection.md`.

- Blender 5.3 Sculpt Controls documents topology auto-masking as limiting influence to connected vertices and allows topology, Face Set and normal-facing restrictions to combine. Adaptation: keep semantic support selection separate from topological distance propagation.
- Blender 4.5 Shortest Edge Paths documents Dijkstra-based vertex paths and identifies edge length as a natural edge cost. Adaptation: radius-bounded accumulated mesh-edge length becomes a deterministic dependency-free surface-distance approximation for brush weights.
- Three.js `BufferGeometry` documents indexed triangles as ordered triples of reusable vertex indices. Adaptation: projected samples retain exact triangle/corner/barycentric ownership and reject stale reordered topology.

## Remaining limitations / next workflow priority

The shortest-edge field is tessellation dependent, not an exact continuous geodesic. A connected semantic region can still be reached if its accumulated edge route lies within the brush radius. There is no screen-space stroke capture, pressure/time sampling, occlusion test, custom falloff curve, collision handling, or topology-changing path remap. Projection stores same-topology barycentric ownership; arbitrary subdivision, remeshing, booleans or face reordering require explicit re-projection/remap.

The next general workflow priority is **topology-aware sculpt falloff quality and reusable stroke editing**: evaluate either a bounded continuous-triangle/geodesic refinement or an editable projected-path representation that can be re-sampled cheaply after support changes, whichever removes more repeated authoring work without turning the library into a full interactive sculpt application. No cyber-android likeness change is claimed in this pass.
