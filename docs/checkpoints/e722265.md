## Reusable capability

Added `deformGeometryInParent()` so one bend/twist/taper/curve/lattice field can reshape several separately owned `BufferGeometry` components in a chosen assembly-local frame. The operation converts component-local vertices through the supplied local-to-parent transform, evaluates existing deformation handles in that parent space, and returns positions to component-local coordinates. Selections remain component-local; topology, UVs, ordinary custom attributes, named face-region provenance and object/material ownership follow the existing deformation contract.

Before this checkpoint, an author either had to merge a layered assembly before a broad cage edit or duplicate/re-express the field in every component's local coordinates. Now one construction field can remain shared while components retain separate materials, transforms, names and export ownership.

## Research

- Blender Foundation, *Lattice Modifier*, Blender 4.5 LTS manual, page updated 2026-08-27, accessed 2026-09-17: multiple objects may use one lattice while per-object influence remains separate. Adapted as explicit construction data, not a live modifier stack.
- Three.js project, r186 *Object3D* / *Matrix4* docs, accessed 2026-09-17: local versus accumulated transforms plus compose/invert semantics. Adapted as an explicit local-to-parent matrix and inverse, not scene traversal.
- Detailed notes: `docs/research/shared-deformation-space.md`.

## Exercised examples

1. Layered organic creature mass: separate skin, dorsal crest and collar use one parent-local lattice; a socket datum is rigid.
2. Layered mechanical service housing: separate shell, upper rail and service inset use another parent-local lattice; mounting foot and pins are rigid.

A mechanical regression additionally proves equivalence to compose-first deformation within `4e-6 m`, including translated, rotated and non-uniformly scaled component placements.

## Rejected approaches

- Merge-before-deform: rejected because it unnecessarily sacrifices separate part ownership.
- Reuse identical geometry-local handle coordinates on transformed parts: rejected because those coordinates no longer describe one physical field.
- Live `Object3D.matrixWorld` traversal in the geometry helper: rejected to keep recipe construction explicit, deterministic and DOM/scene independent.

## Limitations and next workflow priority

The helper represents one explicit parent space. It does not accumulate arbitrary nested hierarchies, mutate object transforms, infer field membership, solve collisions/self-intersections, refit skin/morph data or export a runtime modifier. Positive non-uniform scale is supported; zero/reflected scale is rejected.

Next priority: evaluate a reusable UV/chart and material-region authoring contract for topology-preserving ordinary geometry, so new subjects can receive decals, trims and surface detail without hand-editing UV coordinates after every broad-form change.
