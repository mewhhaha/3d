## Reusable capability

Added `assignFaceMaterials()` and `faceMaterialIndices()` so persistent named face regions can drive Three.js material slots without hand-authored draw-range bookkeeping. The compiler preserves face/index order, positions, UVs, named face-region metadata and same-topology persistent anchors, then emits complete contiguous material groups. Existing complete groups may supply the default ownership, or callers may choose one numeric base material. Conflicting overlapping semantic regions fail explicitly; same-slot overlap is allowed.

`mesh()` now accepts a non-empty material array as well as one material, so ordinary recipes can use the compiled groups without dropping to recipe-local `new THREE.Mesh(...)` construction.

Before this checkpoint, semantic regions already drove sculpt masks, queries and attachments, but face-wise look development still required manually maintained `BufferGeometry.groups`. Now one semantic definition can be reused for both authoring operations and discrete material assignment while rendering groups remain a derived concern.

## Research

- Blender Foundation, *Material Assignment*, Blender 4.5 LTS manual, accessed 2026-09-17: material slots correspond to object parts and selected faces can receive a slot; smooth transitions should instead use shader mixing. Adapted as semantic-face -> discrete-slot compilation, not Blender data-block compatibility.
- Three.js project, r186 `BufferGeometry` documentation, accessed 2026-09-17: groups split indexed geometry into draw calls using material-array indices. Adapted as complete deterministic face-order runs, while semantic names remain separate from group numbers.
- Blender Foundation, *UV Seams*, Blender 4.5 LTS manual, accessed 2026-09-17: seams partition surfaces into UV islands and different areas can use different unwrap strategies. Used as an evidence-based boundary for this pass: material assignment does not masquerade as UV charting.
- Detailed notes: `docs/research/material-regions.md`.

## Exercised examples

1. Stylized organic creature shell: one indexed sphere carries independent `creature.crown` and `creature.muzzle` semantics, then maps them to two accent materials over a base material.
2. Hard-surface service panel: one subdivided housing maps `panel.service` and `panel.header` semantic regions to separate material slots while retaining a separately owned mounting foot.

## Rejected approaches

- Store semantic meaning directly in `BufferGeometry.groups`: rejected because group order/material indices are renderer ownership, while semantic regions already survive other authoring stages independently.
- Reorder triangle indices to consolidate every material into one group: rejected because that would unnecessarily change topology identity and invalidate exact anchors/provenance.
- Couple this pass to UV chart splitting/unwrapping: rejected because face-corner UV seams can require vertex duplication and therefore need an explicit topology-changing provenance contract rather than being hidden inside material assignment.

## Limitations and next workflow priority

This is discrete face-wise material assignment, not smooth shader blending, texture painting, or UV unwrapping. Many alternating region runs can increase draw calls. It only accepts indexed triangles and assumes material slot arrays are supplied by the Mesh. It does not remap material groups through unrelated topology changes automatically; named face-region provenance remains the durable authoring layer.

Next priority: reusable UV chart/seam authoring for selected named regions, with explicit vertex-duplication provenance and transfer/invalidation rules for anchors, weights, tangents and other dependent data before any unwrap/pack result is treated as safe.
