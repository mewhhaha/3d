# Workflow checkpoint — reusable path sculpt selections and local symmetry

Base remote revision: `d0767648cf39aa6473f145b4112a934619728a0d`.
Implementation revision: `da5721f3f6c824fc7bedc07654d52c3794dfe862`.
Capability: author elongated topology-preserving edits on ordinary indexed Three.js `BufferGeometry` from reusable 3D polyline fields, independently place those fields in local frames, and mirror one authored stroke without duplicating point data.

## Accepted change

`src/lib/geometry-sculpt.js` now adds `pathSelection()`, `framedSelection()` and `symmetrySelection()` to the existing point-domain selection algebra. `pathSelection()` evaluates compact Euclidean falloff around a piecewise-linear 3D path, accepts either one positive radius or one radius per authored point, and interpolates radius along each nearest segment. `framedSelection()` evaluates any child selector in a geometry-local authoring frame with meter translation, XYZ-degree rotation and positive scale. `symmetrySelection()` unions a selector with its reflection across a local axis or explicit existing symmetry plane. The selectors remain independent from `pullVertices()`, `inflateVertices()` and `smoothVertices()`: authored stroke data says where influence lies, while brush-style operations still say what to do there.

The implementation reuses the project's existing `symmetry.js` reflection primitives and Three.js r186 `Line3`/`Matrix4` math. It does not add an interactive brush event system, screen-space stroke capture, or a second symmetry convention. Zero-length path segments and invalid radii/scales fail explicitly.

## Research used

See `docs/research/geometry-sculpt-strokes.md`.

- Blender 4.5 LTS Stroke documentation separates stroke method from brush effect and documents 3D Scene spacing for sculpt strokes. Adaptation: keep path selection (`where`) separate from pull/inflate/smooth (`what`) and author the reusable field directly in geometry-local 3D.
- Blender 4.5 LTS Sculpt Symmetry mirrors brush strokes across local axes. Adaptation: mirror selector evaluation across an explicit local plane; nesting symmetry inside `framedSelection()` makes that plane part of the authored frame instead of a world/screen assumption.
- Three.js r186 `Line3` provides clamped closest-point parameters used for nearest-segment distance and endpoint-radius interpolation. `Matrix4.compose()`/`invert()` and a corresponding normal matrix provide the local-frame conversion without introducing a dependency.

## Rejected / bounded behavior

A chain of independent radial selectors was rejected as the primary authoring representation because editing a bend, width transition or placement requires coordinating several unrelated centers. This pass also deliberately rejects the larger problem of interactive stroke capture or geodesic surface tracing: the reusable primitive is a static 3D polyline field that composes with existing named-region and facing masks. Mirror symmetry is the only new symmetry operation; radial/tiling symmetry and interactive correction remain outside this bounded layer.

## Remaining limitations / next workflow priority

`pathSelection()` measures closest Euclidean distance to 3D segments, not geodesic distance over the mesh and not screen-space distance. On thin folded shells an unconstrained path can influence nearby layers, so semantic/facing masks are still important. There is no surface projection/resampling, pressure/time sampling, occlusion test, collision handling, custom falloff curve or automatic path transport through topology changes. `framedSelection()` supports positive scale rather than shear/reflection, and smoothing remains simple density-dependent one-ring Laplacian averaging.

The next general workflow priority is **surface-aware stroke projection/selection**: derive reusable stroke samples against a named support surface using the existing triangle spatial-query layer, constrain them to the intended region/facing, and make curved-surface seams/folds avoid Euclidean bleed onto nearby layers. Start with a bounded deterministic projection/resampling operation rather than a full interactive sculpt system. No cyber-android likeness change is claimed in this pass.
